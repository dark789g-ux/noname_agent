# 开局 LLM 选将

## 使用

1. 启用「LLM AI 助手」，配置默认后端或各座位后端。
2. 如需自动选择自己的武将，开启真人接管；本地 AI 后端不发送模型请求。
3. 新开单机普通身份对局。沿用正常身份候选、单／双将、武将版本和可选势力规则。
4. 等待面板可「跳过剩余 LLM 选将」：保留已完成合法结果，未完成自动回退；不关闭正式对局的 LLM。

配置在选将开始冻结，局中修改下一局生效。继续游戏、固定结果优先；联机、身份变体和乱斗保持原选将流程。
无需新配置、数据库迁移或 fs 接口升级；更新前端后刷新并新开一局即可。

## 边界

- 主公、本人、其余座位依次处理；其余 LLM 座位最多两人一批。批内候选互斥，按座位顺序提交后统一回收未选候选；池不足时串行。
- 本地 AI 座位保留原流程。LLM 失败时使用冻结候选内的本地身份启发式选择（主公优先主公候选、忠臣偏向主公势力），避免人工补选。
- 模型仅收到自己座位与身份、离主公初始距离与上下家步数、候选属性技能、规则及已公开主公信息（含体力与技能）；不采集其他隐藏身份、候选、对话或牌堆。
- 选将与正式对局共用本局日志归档，但 sessionKey 隔离。选将远端会话结束即清理；正式上下文仅保留本座位结果和不超过 200 字的理由。
- 跳过和总预算到期都贯通取消信号；轮次及身份／桌位检查拒绝迟到写回。主动取消后不自动修复或重建请求。
- 真人全局托管锁与普通牌局 LLM 决策仍在 `gameStart` 才激活。

## 实现与验证

实现位于 `apps/core/noname/llm/character-selection/`；`mode/identity.js` 只保留阶段接入点。
模式通过 `noname.js` 公共导出调用服务，避免独立打包时生成第二份日志／摘要单例。
`candidates`、`validation`、`decision`、`batch`、`state` 分别处理冻结候选、校验、独立请求、分批与取消状态。
`controller` / `identity` 负责引擎适配，`summary` 隔离上下文，`progress` 提供等待界面。

测试使用模拟引擎和 provider，实际执行身份模式选将阶段，覆盖单双将、版本／势力、混合后端、真人手动、本地 AI、跳过、故障、重入和非目标模式。
可运行 `pnpm -F noname test:llm-character-selection` 验证本功能与直接关联的传输取消。
仅运行本目录的指定测试文件以及直接关联的传输、生命周期、座位日志测试；不要运行全量测试或全包 lint。
真实 OpenAI/Codex/agy 服务、浏览器布局、Electron 和移动端仍需人工验收。
