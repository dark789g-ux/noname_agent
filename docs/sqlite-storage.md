# 本地浏览器的 SQLite 存储

本地浏览器通过 `@noname/fs` 读写 SQLite，数据库固定在项目根目录的 `data/noname.sqlite`。`pnpm dev` 和 `pnpm start` 使用同一位置，不随前端端口或启动目录变化。连接同一个本地服务的浏览器共用数据；已打开页面中的配置不会主动实时刷新，重新加载页面后读取最新配置。

本次范围是浏览器通过 Node.js 本地服务运行。Electron、Cordova 等原生客户端继续使用原有 IndexedDB；独立可执行文件的 SQLite 原生模块打包不在本次范围内。

## 启动

```powershell
pnpm install
pnpm dev
```

浏览器默认打开 `http://127.0.0.1:8080`，文件与存储服务默认监听 `8089`。构建后通过 `pnpm start` 运行。SQLite 驱动使用 `better-sqlite3`，其原生构建已加入工作区允许列表。

默认配置仍来自 `apps/core/game/config.json`。玩家修改写入 SQLite，不会改写源码中的默认配置文件。

## 首次迁移

1. 页面检查 SQLite 的初始化标记。
2. 尚未初始化时，只读当前站点的主 IndexedDB 和独立 LLM 日志库。
3. 配置、模式数据、录像、图片、音频、LLM 完成日志、活动检查点和实例租约分别暂存到 SQLite。图片、音频包括实际内容。
4. 完整暂存成功后，在一个 SQLite 事务中提交数据与初始化标记。多个页面同时迁移时，首次成功提交的页面为准。
5. 原 IndexedDB 保留。迁移中断不会留下可用一半的主库，重新加载页面可以重新迁移。

**首次使用请从保留旧数据的原地址打开游戏。** IndexedDB 按协议、主机、端口隔离。例如 `127.0.0.1:8080` 无法读取 `127.0.0.1:8081` 或 `localhost:8080` 的旧库。如果首次打开的地址没有旧数据，SQLite 会初始化为空，游戏使用默认配置。

初始化后，其他浏览器的旧 IndexedDB 不再自动导入。原有“导出游戏设置 / 导入游戏设置”仍可用于手动迁入配置与模式数据；录像可使用录像菜单的导入功能。这些入口不是完整数据库备份。

## 保存和故障处理

- 普通数据库接口保留回调和 Promise 用法，写入提交后才通知成功。
- 同一页面按调用顺序保存；跨页面的读改写事务检查数据版本，冲突后重新读取并重试。
- 网络中断、服务未启动或 SQLite 不可读写时，显示错误和“重试”按钮，相关存储操作保持等待。恢复本地服务后点击重试。
- 不自动回退到 IndexedDB。重试同一个写请求不会重复提交已经成功但响应丢失的事务。
- 重置游戏设置会清理 SQLite 中对应的数据，保留初始化标记，不会再次自动导入旧 IndexedDB。

## 数据结构与备份

同一个 SQLite 文件包含两组逻辑数据：`main` 和 `logs`。`records` 表使用 `namespace`、`store`、`key` 定位记录，`value` 是保存结构化数据的 BLOB；其中的图格式编码保留 Blob/File、二进制视图、日期、Map/Set、undefined、循环引用等类型。录像的数字键与同内容的字符串键分别保存。

`metadata` 保存初始化信息，`revisions` 用于并发检查，`migrations` / `staged_records` 保存尚未提交的迁移，`requests` 用于写请求去重。这些辅助表与数据一起备份。

数据库采用 WAL。备份前停止所有使用该数据库的本地服务，确认进程已退出，再复制整个 `data` 目录；恢复时同样先停止服务，再恢复该目录。不要在服务运行时仅复制 `noname.sqlite` 而遗漏其旁边的 WAL 文件。

`data/` 已加入 Git 忽略。文件服务拒绝通过静态下载、文件读取、写入和删除接口访问数据库目录；Vite 也拒绝直接提供数据库及其旁边的 SQLite 文件。

## 验证

```powershell
pnpm test:storage
pnpm -F @noname/fs build
pnpm -F noname build
```

测试使用独立的临时数据库，不初始化项目实际的 `data/noname.sqlite`。
